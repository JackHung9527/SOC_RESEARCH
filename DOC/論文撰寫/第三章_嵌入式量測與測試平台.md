## 3.1 系統架構

本研究建構的測試平台同時扮演兩個角色：其一為**電池特性激勵與真值量測平台**，由可程式直流電源供應器與可程式電子負載對電池施加受控的充放電激勵，並以高精度儀錶記錄電壓、電流真值；其二為**嵌入式估測標的**，由一顆 STM32 微控制器搭配 INA226 電流／電壓量測晶片，作為三種 SOC 估測演算法的實際運行載體。兩個角色共用同一顆受測電池（Device Under Test, DUT）與同一條高功率量測迴路，使得「儀錶量到的真值」與「MCU 估出的 SOC」可逐點對齊比較。整體架構如圖 3-1 所示。

```
                    ┌──────────────────────────────────────────┐
                    │            上位機 (Python orchestrator)     │
                    │   round_runner.py / gitt_ocv_runner.py     │
                    │   BenchInterlock · SafetyGuard · CycleLog   │
                    └───────┬───────────────┬───────────────┬────┘
                  SCPI/USB  │      SCPI/USB │       VCP/USB │
                  9600 8N1  │      9600 8N1 │     115200 8N1│
              ┌─────────────┴──┐  ┌─────────┴──────┐  ┌─────┴───────────┐
              │ IT6302 直流電源 │  │ IT8512A+ 電子負載│  │ STM32G071 + INA226│
              │ (充電路徑 CC-CV) │  │ (放電路徑 CC)   │  │ (嵌入式估測標的)  │
              └───────┬─────────┘  └────────┬───────┘  └────────┬────────┘
                      │  充電           放電 │                I²C │ 400 kHz
                      └──────────┬───────────┘                    │
                                 ▼                                ▼
                       ┌──────────────────┐  跨 Rshunt   ┌────────────────┐
                       │   DUT 電池 (NMC)  │──10 mΩ shunt─│ INA226 (0x40)  │
                       │  2000 mAh, 4.2 V  │              │ V+/V-/VBUS 量測│
                       └──────────────────┘              └────────────────┘
```

平台各組成的角色與規格整理如表 3-1。受測電池為一顆客製化 NMC 鋰離子電池（標稱容量 2000 mAh，充電截止電壓 $V_{cv}=4.2$ V，放電截止電壓 $V_{cut}=2.5$ V，最大放電電流 4 A）。

| 組成 | 型號／規格 | 介面 | 角色 |
|---|---|---|---|
| 微控制器 | STM32G071RBTx（Nucleo-G071RB，板載 ST-Link V2.1），SYSCLK 64 MHz | — | 嵌入式估測標的、heartbeat 輸出 |
| 電流／電壓量測 | INA226，I²C 位址 0x40，$R_{shunt}$ 標稱 10 mΩ | I²C1 @ 400 kHz | MCU 端 V／I 取樣 |
| 直流電源 | ITECH IT6302（CC-CV） | SCPI / USB-CDC，9600 8N1 | 充電路徑 + 充電真值 |
| 電子負載 | ITECH IT8512A+（CC 模式） | SCPI / USB-CDC，9600 8N1 | 放電路徑 + 放電真值 |
| 上位機 | Python orchestrator（樹莓派／PC） | USB 三埠 | 排程、互鎖、紀錄 |

量測迴路採單點共地的 Kelvin（四線）連接：電池正極經 10 mΩ shunt 串接至電源／負載，INA226 的 IN+／IN− 緊貼 shunt 兩端做差動電流量測、VBUS 量測電池端點電壓，並由電池負極就近單點接出邏輯地，以避免 shunt 壓降耦合進邏輯供電（詳細腳位與訊號完整性見附錄 A 與 `MCU/docs/wiring.md`）。充電與放電為兩條獨立路徑，由上位機在軟體層確保任一時刻僅一條路徑帶電（3.5 節）。

上位機與三個設備各以一條 USB 序列埠通訊：IT6302 與 IT8512A+ 走 SCPI 指令集，STM32 經 USART2 將 1 Hz heartbeat 輸出到 ST-Link 虛擬序列埠（VCP），上位機由此解析 MCU 端的 V／I／SOC 估測值。如此，同一充放電事件同時被「儀錶真值」與「MCU 估測」兩路獨立記錄，構成第四章逐點誤差分析的資料基礎。

## 3.2 STM32 韌體骨架（USER_CODE 框架與 100 µs 系統節拍）

為使第四章三種 SOC 演算法在「完全相同的執行環境」下運行，本研究先建立一套統一的裸機韌體骨架，所有估測模組皆掛載於此骨架之上，避免因排程或時序差異污染比較結果。骨架以 STM32CubeIDE 產生的 HAL 專案為基底，於 `USER_CODE/` 目錄下組織應用層程式，核心設計為「100 µs 基底節拍 + once／loop 應用入口 + 模組化 driver」三者。

**100 µs 基底節拍**：以 TIM6 基本計時器產生 100 µs 中斷，其中斷服務常式僅將全域計數器 `g_softWareTimCnt` 遞增，不在中斷內做任何列印或運算，避免在 100 µs 尺度上阻塞或飽和 UART。上層需要週期性事件時，呼叫 `softWareTimTick_100us(cmd, cnt, Period)` 軟體計時器：以 100 µs 為單位累計至指定 `Period` 後回傳逾時旗標。例如 1 Hz heartbeat 即以 `Period = 10000`（10000 × 100 µs = 1 s）實現。此設計使「硬體中斷只計數、應用層在主迴圈輪詢」職責分離，是後續 EKF／動態阻抗等估測模組共用的時間基準。

**once／loop 應用入口**：`main.c` 在初始化後呼叫一次 `once()`、並於 `while(1)` 內反覆呼叫 `loop()`。`once()` 啟動 TIM6 中斷、依序初始化各 driver（`uart_debug` → `i2c_bus` → `ina_cal`）、印出可供上位機 grep 的開機橫幅，並對 INA226 做一次 I²C 探測（探測失敗時以警告續行，不硬性中止——量測平台須在感測器缺席時仍能運行）。`loop()` 依序驅動各 driver 的 `handle()`，再以軟體計時器分派 1 Hz heartbeat。

**模組化 driver**：應用功能切分為獨立子模組，各自含 `init()`／`handle()` 並透過 `global_includes.h` 的 driver 區塊統一納入。目前已實作之模組如表 3-2。

| 模組 | 職責 |
|---|---|
| `uart_debug` | USART2 @ 115200 的 IT-driven 環形緩衝 TX，並 retarget `printf` |
| `i2c_bus` | I²C1 @ 400 kHz master，封裝對 INA226 的暫存器讀寫 |
| `ina226` / `battery_monitor` | INA226 組態（CONFIG／CAL）、單次取樣、取得最新 V／I／P 快照 |
| `ina_cal` | 14 點校正 LUT 之載入與套用（`ina_cal_apply`），UART CLI 燒錄／讀回 |
| `soc_soh_calc` | SOC／SOH 估測（第四章三方法掛載於此） |

heartbeat 每秒翻轉使用者 LED 並輸出一行狀態，例如 `[12s] alive V=3940.2mV I=+198.9mA Ical=+201.0mA P=783.6mW i2c=ok ina=present cal=on`，其中 `Ical` 為套用校正 LUT 後的電流、`cal=on/off` 指示 LUT 是否有效載入。INA226 韌體預設 `Current_LSB = 152.5879 µA/LSB`（依 datasheet 以 $I_{max}=5$ A、$R=10$ mΩ 計），校正後改以 LUT 後處理修正（3.3 節）。14 點 LUT 經 UART CLI 燒入 STM32 內部 Flash page 63（位址 0x0801_F800），開機自動載入，故 MCU 可直接吐出校正後電流值。此骨架即為第四章三種估測方法的共同載體，三者僅替換 `soc_soh_calc` 內的估測核心，其餘時序、I/O、量測路徑完全一致，確保比較之公平性。

## 3.3 INA226 多點線性內插校正

第四章所有 SOC 方法都以電流積分為基礎（庫倫計數為直接積分，EKF 與動態阻抗亦需準確電流），故電流量測精度是整個平台的根。INA226 出廠後的原始讀值存在顯著系統性偏差，必須先行校正。

**校正前偏差**：以電子負載拉定電流為真值，比對 MCU 原始讀值，發現 INA226 電流系統性偏高約 **15.8%**（200 mA 時讀為 230.4 mA），主因是 shunt 實際阻值偏離標稱 10 mΩ，加上 PCB 走線串聯阻抗與 ADC 零點偏移。此偏差若不校正，將直接以同等比例污染所有 SOC 估測。

**校正設計**：採分方向各 7 點、合計 14 點的線性內插校正。校正電流點為

$$\{0,\ 0.05,\ 0.10,\ 0.50,\ 1.00,\ 1.50,\ 2.00\}\ \text{A}$$

充電方向以 IT6302、放電方向以 IT8512A+ 提供真值；之所以分方向各建一張 LUT，是因 INA226 的零點偏移對電流方向可能不對稱。選點兼顧低電流區（offset 主導，0、0.05、0.10 A）與高電流區（shunt 線性度與純比例縮放，0.5～2.0 A，其中 2.0 A = 1C @ 2000 mAh）。每點時序為：寫入設定值並以 readback 驗證（容差 $\max(5\ \text{mA},\,5\%)$）→ 3 s 穩態 → 5 s 並行採樣（儀錶 `MEAS:CURR?` 每 0.4 s、MCU heartbeat 每 1 s）取平均。

**校正觀察**：原始數據呈現三項一致規律：(1) 充放電同電流點的比值（ref/mcu）一致到小數第三位，確認 shunt 量測對方向無偏；(2) 0 A 零點偏移為 +1.10 mA（兩方向同號）；(3) 高電流區（> 500 mA）比值收斂至 0.880，等價於 shunt 實際阻值 $\approx 10/0.880 = 11.36$ mΩ（較標稱 +13.6%），或等價於將 `Current_LSB` 改為 $152.5879 \times 0.880 = 134.3$ µA/LSB。低電流區比值下降至 0.85，符合「固定 +1.10 mA offset 在小電流上佔比放大」的純 offset 主導模型。

**校正模型**：採分段線性內插（piecewise-linear），不使用多項式擬合。給定 MCU 讀值 $I_{mcu}$，於 LUT 中找包夾區間 $[m_k, m_{k+1}]$ 後線性內插得真值估計 $I_{ref}$；超出範圍則以首／末段斜率外插。此法相較單一比例或多項式更能同時吻合低電流 offset 與高電流線性兩種行為。

**內插驗證**：以未列入校正表的 4 個獨立電流點（0.30、0.75、1.25、1.75 A）驗證 LUT 內插預測對真值的誤差，結果如表 3-3。

| 目標 (A) | 真值 (mA) | MCU 原始 (mA) | LUT 預測 (mA) | 預測誤差 (mA) |
|---:|---:|---:|---:|---:|
| 0.300 | 298.31 | 340.20 | 298.10 | −0.21 |
| 0.750 | 748.78 | 851.32 | 748.56 | −0.21 |
| 1.250 | 1248.46 | 1418.52 | 1248.29 | −0.17 |
| 1.750 | 1748.61 | 1986.30 | 1748.44 | −0.16 |

全範圍誤差 **< 0.21 mA**，相當於 1.75 A 的 **0.012%**（< 1‰）。校正前原始偏差 +41～+238 mA（約 +13%～+16% 系統性偏高），校正後降至 < 1‰，連同 shunt 容差一併校正，實測精度優於 INA226 datasheet 標稱的 ±0.1%（datasheet 不含 shunt 容差）。此校正成果為第四章所有以電流積分為基礎的估測提供了可信賴的量測根基。校正過程完整紀錄見 [DOC/校正紀錄/2026-05-07_ina226_calibration.md](../校正紀錄/2026-05-07_ina226_calibration.md)。

## 3.4 電源與電子負載之 SCPI 自動化

長時間（單輪 16～18 h、GITT 約 46 h）無人值守實驗要求上位機對儀器的每一個指令都「下達即確認生效」，否則一個未生效的設定就可能毀掉整批數據或損傷電池。本研究在 SCPI 自動化層處理了兩個關鍵陷阱。

**陷阱一：IT6302 `APPL` 指令不可靠更新 CURR**。IT6302 的 `APPL V,I` 複合指令在連續寫入時，不保證更新電流限值，通道可能沿用前一次的 CURR 設定。實測曾出現首次充電本應 1 A 卻灌出接近 1C（2 A）的失控情形。修正紀律為：**分開**下 `set_voltage` 與 `set_current`，並在輸出致能前以 `CURR?` readback 驗證；若回讀值與目標差距超過容差 $\max(5\ \text{mA},\,5\%\times I_{target})$ 則重試一次，再不過則拋出例外中止該步，絕不在電流未確認的情況下致能輸出。此紀律同時套用於 `round_runner` 與 `gitt_ocv_runner` 的每一次充電設定。

**陷阱二：PSU 關閉後的殘留電流誤判**。終止充電時下 `CHAN:OUTP OFF` 後，IT6302 內部 A/D 更新率僅約 1～2 Hz，輸出 FET 亦需時間洩放殘餘電流，故「關閉後固定 sleep 100 ms 再硬判一次」會在合法的 0.1C taper 終止後仍讀到 $I \approx 100$ mA，誤判為「PSU 沒關」而觸發緊急停機。修正為**輪詢驗證**：送出 OFF 後，以 150 ms 為間隔輪詢 `MEAS:CURR?`，最長等待 2 s，一旦 $|I| \le 50$ mA 即判定關閉成功提早通過；2 s 內始終高於門檻才判失敗。此法在不犧牲安全性的前提下，容忍了儀器固有的量測延遲。

上述兩項修正體現了本平台的設計原則：**所有對外部設備的狀態改變都必須以回讀（readback／poll）驗證生效，而非假設指令即時、無誤地被執行**。這是長時間自動化實驗資料品質的根本保障。

## 3.5 BenchInterlock 安全互鎖機制

單顆電池測試平台沒有 BMS 作為硬體保護，軟體互鎖即是最後一道防線。本研究以 `BenchInterlock` 狀態機與 `SafetyGuard` 雙層守護，防止兩類可能損毀電池或設備的事故。

**BenchInterlock 狀態機**防止兩種錯誤的儀器組合（圖 3-2）：

```
   IDLE ──start_charge──► CHARGING ──stop_charge──► COOLDOWN ──(t≥deadtime)──► IDLE
   IDLE ──start_discharge──► DISCHARGING ──stop_discharge──► COOLDOWN ──(t≥deadtime)──► IDLE
圖 3-2  BenchInterlock 狀態轉移；任何違反此圖的轉移都拋例外並強制 emergency_stop
```

其防護的兩類失效模式為：(A) 電源輸出與電子負載同時致能——兩者對拉會使不可預期方向的電流流經電池，任一控制迴路的瑕疵都可能導致過充或熱失控；(B) 不經休息直接由充電切換到放電（或反向）——電池需時間鬆弛、操作者亦需確認匯流排狀態。狀態機以三項紀律落實防護：每次致能某一輸出前，先驗證**另一**設備確實關閉（`_load_off_verified`／`_psu_off_verified`，後者即 3.4 的輪詢驗證）；每次關閉後強制 5 s **dead-time** 冷卻才允許下一次轉移；任何違反狀態圖的呼叫立即拋出 `BenchInterlockError` 並強制雙路關斷。`start_discharge` 在仍處 `CHARGING` 時會直接拒絕，要求顯式先 `stop_charge`，杜絕捷徑切換。

**SafetyGuard 雙層電壓／電流封套**：第一層為**絕對封套**，即化學體系的硬限值（NMC：$V_{abs}=[2.50,\ 4.25]$ V、$|I| \le 4.30$ A 之接線限值），跨越即單點立即跳脫、不去抖；第二層為**軟跳脫封套**，緊貼使用者設定值外緣（充放電截止再外推 50 mV），需連續 $N=2$ 個壞樣本才跳脫，以容忍正常操作中的暫態雜訊，但仍遠在絕對地板之前動作。各 phase 腳本每取樣一次即呼叫 `guard.check(v, i)`，任何跳脫拋出 `SafetyAbort`，並由腳本的 `finally` 區塊經 `emergency_stop()` 將雙路置於安全狀態。

此雙層設計使「化學紅線零容忍、操作雜訊有去抖」兩個看似衝突的需求得以並存，是長時間實驗能安全無人值守的前提。

## 3.6 跨輪自動化測試協定（round_runner 與 cycle_log）

第四章的方法比較需要橫跨多種放電 C-rate、且可跨多輪累積的乾淨資料。`round_runner.py` 即為此設計的跨輪自動化協定。

**一輪的結構**：一輪（round）由四個 (充電, 休息, 放電, 休息) 區塊串成，充電固定為 0.5C（高倍率充電會傷害電池並污染 SoH 基準），放電依序掃過 $\{0.5,\ 1.0,\ 1.5,\ 2.0\}$C 四種倍率，每次轉向間休息 30 min。一輪約 16～18 h（2000 mAh NMC）。協定流程如表 3-4。

| 步驟 | 動作 | 倍率 | 目的 |
|---|---|---|---|
| 1 | 充電 | 0.5C → 截止 | 充飽 |
| 2 | 休息 | — | 30 min 鬆弛 |
| 3 | 放電 | 0.5C → 截止 | 基準 V(SoC) @ 0.5C |
| 4 | 休息 | — | 30 min |
| 5–8 | 充電→休息→放電 1.0C→休息 | | rate-capability |
| 9–12 | 充電→休息→放電 1.5C→休息 | | rate-capability |
| 13–16 | 充電→休息→放電 2.0C→休息 | | rate-capability |

**CC-CV 充電終止判斷**：充飽偵測有兩條路徑（避免單點誤觸發）。其一為**正常終止**——$V \ge V_{cv}-100\ \text{mV}$ 且 $I \le 0.1$C，且**連續滿足 3 秒**、總經過時間 $\ge 30$ s 才成立（持續性 + 穩態時間，封鎖「$t=0$ 時開路電壓近 $V_{cv}$、電流尚為 0」的瞬時假觸發）；其二為**已飽電旁路**——操作者放上接近飽電的電池時，在起步 5 s 視窗內若 $V \ge V_{cv}-30\ \text{mV}$、$I < 50$ mA 且從未進入真正 CC，則整步跳過（記 `note=already_full`），免去對隔夜飽電電池空跑數分鐘無意義的 CV taper。

**放電中的 dV/dI 擾動**：放電步在 CC 基礎上週期性注入電流擾動，直接服務第四章的動態阻抗法 [2]。每 60 s 由基礎倍率短暫步降到 0.2C、dwell 1 s 後步回，取步降前後兩個穩態樣本計算 $\Delta V/\Delta I$，即該 SOC 下的動態阻抗估計；基礎倍率越高，$\Delta I$ 越大，dV/dI 訊噪比越好，故四種放電倍率全數注入擾動。庫倫計數涵蓋擾動期間的秒數（含 dwell），避免約 3% 的庫倫低估。

**持久化 cycle_log**：每完成一個充電或放電步，即向 `cycle_log.csv` 追加一列，記錄 `cycle_id`、`round_id`、方向、倍率、起訖電壓、安時量、容量保持率與累積 Ah。容量保持率定義為

$$q_{retention}\ (\%) = 100 \times \frac{q_{actual}}{q_{rated}}$$

`cycle_id` 在每次放電到截止時遞增，充電繼承其後放電的 `cycle_id`（一對充放電共用一個 cycle_id）；跨次執行時程式自動讀回既有 CSV，續接 `round_id`／`cycle_id`／累積 Ah，達成無縫跨輪累積。本研究以連續三輪 fresh-cell baseline 驗證 0.5C cycle 的容量保持率是否落在 95～100%、並計算輪間變異性，作為進入後續測試前的資料品質閘門（變異性分析見第五章）。

## 3.7 GITT pseudo-OCV 表建立

第四章的 EKF 觀測方程需要一條 OCV–SOC 對應曲線，否則 EKF 無法實作。如第二章所述，OCV 查表作為獨立即時方法與本研究的 rate-capability 協定不相容，故折衷以 GITT（恆電流間歇滴定法，Galvanostatic Intermittent Titration Technique）標準協定一次性建立 pseudo-OCV 表，專供 EKF 使用 [待補引用]。此流程由 `gitt_ocv_runner.py` 自動化。

**協定參數**：SOC 步長 5%（1% 過密、CP 值差）、每步靜置 60 min（30 min 殘餘漂移仍約 2～5 mV）、CC 倍率 0.5C，雙向進行——放電向 100%→約 0%、充電向約 0%→100%，各 20 步。流程自動先 CC-CV 充飽（PHASE 1，約 2.5 h），再跑放電 GITT（PHASE 2，約 22 h），最後跑充電 GITT（PHASE 3，約 22 h），結束時電池恢復至滿電，可安全串接後續 round。總時程約 **46 h**，一次性建表。

**平衡電壓與 pseudo-OCV**：每步 CC 移動 5% SOC 後靜置 60 min，取靜置末段最後 30 s 電壓平均為該 SOC bin 的平衡電壓 $V_{eq}$；並計算靜置末 5 min 的 $\mathrm{d}V/\mathrm{d}t$（mV/min）以監看是否充分鬆弛。為消除充放電遲滯迴路，pseudo-OCV 取同一 SOC bin 上放電向與充電向 $V_{eq}$ 之平均：

$$V_{pseudo}(SOC) = \frac{V_{eq}^{\,disch}(SOC) + V_{eq}^{\,chg}(SOC)}{2}$$

充電 GITT 為使端電壓對建表有意義，刻意維持在嚴格 CC（每步在 $V \ge V_{cv}-5\ \text{mV}$ 即停，避免 CV taper 使載流端電壓失去資訊）。

**輸出產物**：三個共用時間戳的 CSV——`gitt_trace_*.csv`（完整取樣級時序）、`gitt_summary_*.csv`（每步一列，含靜置 5/15/30/45/60 min 的電壓與 $V_{eq}$、$\mathrm{d}V/\mathrm{d}t$）、`ocv_table_*.csv`（最終 SOC × $V_{disch}$ × $V_{chg}$ × $V_{pseudo}$）。最後一張即第四章 EKF 觀測方程所用的 OCV–SOC 對應表。

至此，本章已交代第四章三種 SOC 估測方法所需的全部基礎設施：統一的韌體載體（3.2）、可信的電流量測（3.3）、可靠的儀器自動化（3.4）、安全的實驗環境（3.5）、乾淨且可累積的測試數據（3.6）與 EKF 所需的 OCV 表（3.7）。下一章將在此平台上，依「原理 → 演算法 → STM32 實作 → 實驗結果」的一致結構，分別實作並公平比較庫倫計數法、擴展卡爾曼濾波器與動態阻抗法。
